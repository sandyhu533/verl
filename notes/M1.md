## M1.1 — 数据契约 (`gsm8k.py`, 20 min)

### 关键产出：每个 veRL 数据集必须生成的 5 列 schema

| 列名 | 类型 | 作用 |
|---|---|---|
| `data_source` | str | reward_fn 注册表的路由键 |
| `prompt` | list[dict] | chat 格式消息（role/content），后续由 tokenizer 处理 |
| `ability` | str | 指标分组标签，例如 `"math"` |
| `reward_model` | dict | `{"style": "rule", "ground_truth": "42"}` — RLVR 场景核心 |
| `extra_info` | dict | 携带 `index`/`split`/原始问题，不送入模型 |

### 关键函数：`make_map_fn(split)`

**功能**：HuggingFace datasets 的 `.map()` 闭包工厂，把 GSM8K 原始 `{question, answer}` 两列转成 veRL 的 5 列 schema。`split` 参数用来在 `extra_info` 里打标签（train/test）。

```python
def make_map_fn(split):
    def process_fn(example, idx):
        question_raw = example.pop("question")                # 1. 弹出原始问题（含数学题干）
        question = question_raw + " " + instruction_following # 2. 拼接 CoT 提示 "Let's think step by step..."
        answer_raw = example.pop("answer")                    # 3. 弹出包含推理过程+最终答案的长文本
        solution = extract_solution(answer_raw)               # 4. 从 "#### 42" 格式中抽出 "42"（见 L27-32）
        data = {
            "data_source": data_source,                       # 5. 固定为 "openai/gsm8k" —— reward_fn 用这个字符串路由
            "prompt": [                                       # 6. chat 格式是 list[dict]，不是 str
                {
                    "role": "user",                           #    单轮对话只有 user 一条
                    "content": question,
                }
            ],
            "ability": "math",                                # 7. 分组标签，后续 wandb 按 ability 聚合指标
            "reward_model": {                                 # 8. RLVR 核心：ground_truth 让 rule-based RM 能打分
                "style": "rule",                              #    style=rule → 调用规则函数而非神经网络 RM
                "ground_truth": solution,
            },
            "extra_info": {                                   # 9. 诊断信息，永远不送模型
                "split": split,
                "index": idx,                                 #    方便 shuffle 后反查原始行
                "answer": answer_raw,
                "question": question_raw,
            },
        }
        return data
    return process_fn
```

**跳过**：argparse、HDFS copy 分支、`extract_solution` 的正则细节。

## M1.2 — 启动面 (`run_qwen2-7b.sh`, 15 min)

### 目标
把 33 行 override 按前缀分类，能在纸上画出完整 config 树。

```
config
├── data.*              # 数据层：train_files, batch_size, max_prompt_length, max_response_length
├── actor_rollout_ref
│   ├── model.*         # 共享：path, enable_gradient_checkpointing, use_remove_padding
```

### 记住 3 个关键字段（M3/M4/M5 都会用）
- `actor_rollout_ref.rollout.n=5` — GRPO 的组大小（每个 prompt 采 5 条 response）

### 关键函数 2：`run_ppo()` (L50-106)

**功能**：初始化 Ray 集群，把 `TaskRunner` 包成 Ray remote actor 运行。一切分布式工作的起点。`TaskRunner` 跑在 Ray worker 上而非 driver，这样 driver 只保留协调职责。

```python
def run_ppo(config, task_runner_class=None) -> None:
    if not ray.is_initialized():
        default_runtime_env = get_ppo_ray_runtime_env()       # 1. 预设环境变量（TOKENIZERS_PARALLELISM=true, NCCL_DEBUG=WARN, VLLM_LOGGING_LEVEL=WARN, VLLM_ALLOW_RUNTIME_LORA_UPDATING=true）
        ray_init_kwargs = config.ray_kwargs.get("ray_init", {})
        runtime_env_kwargs = ray_init_kwargs.get("runtime_env", {})

        if config.transfer_queue.enable:                      # 2. M7 的零拷贝模式需要额外环境变量
            runtime_env_vars = runtime_env_kwargs.get("env_vars", {})
            runtime_env_vars["TRANSFER_QUEUE_ENABLE"] = "1"
            runtime_env_kwargs["env_vars"] = runtime_env_vars

        runtime_env = OmegaConf.merge(default_runtime_env, runtime_env_kwargs)  # 3. 用户 runtime_env 覆盖默认
        ray_init_kwargs = OmegaConf.create({**ray_init_kwargs, "runtime_env": runtime_env})
        ray.init(**OmegaConf.to_container(ray_init_kwargs))   # 4. 启动/连接 Ray 集群

    if task_runner_class is None:
        task_runner_class = ray.remote(num_cpus=1)(TaskRunner)  # 5. 把 TaskRunner 包成 Ray actor（不要调度到 head node）

    # 6. 可选：nsys profiler 模式。只有 profiling 时才走这条
    if (is_cuda_available and config.global_profiler.tool == "nsys" ...):
        nsight_options = ...
        runner = task_runner_class.options(runtime_env={"nsight": nsight_options}).remote()
    else:
        runner = task_runner_class.remote()                   # 7. 普通路径：spawn 一个 TaskRunner Ray actor

    ray.get(runner.run.remote(config))                        # 8. 远程调用 run(config)，阻塞到训练结束
```

**关键观察**：所有 verl 训练的 "真正入口" 是 `TaskRunner.run()`，它跑在 Ray worker actor 里，不是 driver。

### 关键函数 3：`TaskRunner.add_actor_rollout_worker()` (L124-176)

**功能**：根据 `actor_rollout_ref.actor.strategy` 选择具体 Worker 实现（legacy FSDP / legacy Megatron / new engine），把它注册到 `role_worker_mapping`。新实现把 ref policy 和 actor rollout 融合进同一个类（FusedWorker 雏形）。

```python
def add_actor_rollout_worker(self, config):
    from verl.single_controller.ray import RayWorkerGroup
    from verl.trainer.ppo.ray_trainer import Role

    use_legacy_worker_impl = config.trainer.get("use_legacy_worker_impl", "auto")

    # 分支 A：新 model engine（推荐路径）
    if use_legacy_worker_impl == "disable":
        from verl.workers.engine_workers import ActorRolloutRefWorker  # 1. 新统一 Worker 类
        actor_rollout_cls = ActorRolloutRefWorker
        ray_worker_group_cls = RayWorkerGroup

        lora_rank = config.actor_rollout_ref.model.get("lora", {}).get("rank", 0)
        if lora_rank <= 0:
            lora_rank = config.actor_rollout_ref.model.get("lora_rank", 0)
        ref_in_actor = lora_rank > 0 or config.actor_rollout_ref.model.get("lora_adapter_path") is not None
        # 2. 关键：LoRA 场景可以省掉独立 ref worker —— adapter off 时 base model 就是 ref，节省显存

        if need_reference_policy(config) and not ref_in_actor:
            role = Role.ActorRolloutRef                      # 3. 三合一 role：actor + rollout + ref policy 共用一个 worker
        else:
            role = Role.ActorRollout                         # 4. 二合一：只有 actor + rollout
        self.role_worker_mapping[role] = ray.remote(actor_rollout_cls)  # 5. 包成 Ray remote class
        self.mapping[role] = "global_pool"                   # 6. 放到默认 GPU pool
        return actor_rollout_cls, ray_worker_group_cls

    # 分支 B：legacy FSDP（老代码路径，M6 会看）
    if config.actor_rollout_ref.actor.strategy in {"fsdp", "fsdp2"}:
        from verl.workers.fsdp_workers import AsyncActorRolloutRefWorker
        actor_rollout_cls = AsyncActorRolloutRefWorker
        ray_worker_group_cls = RayWorkerGroup

    # 分支 C：legacy Megatron（M9 涉及）
    elif config.actor_rollout_ref.actor.strategy == "megatron":
        from verl.workers.megatron_workers import AsyncActorRolloutRefWorker
        actor_rollout_cls = AsyncActorRolloutRefWorker
        ray_worker_group_cls = RayWorkerGroup

    # 分支 D：veomni/torchtitan/mindspeed 只在新实现中支持，legacy 直接报错
    elif config.actor_rollout_ref.actor.strategy in {"veomni", "torchtitan", "mindspeed"}:
        raise NotImplementedError(...)

    self.role_worker_mapping[Role.ActorRollout] = ray.remote(actor_rollout_cls)  # 7. legacy 分支只注册二合一 role
    self.mapping[Role.ActorRollout] = "global_pool"
    return actor_rollout_cls, ray_worker_group_cls
```

**两点需要记住**：
1. `actor_rollout_cls` 是一个未实例化的 Python 类（被 `ray.remote` 装饰），不是实例 —— 真正 spawn 在 M2 的 `RayWorkerGroup` 构造函数里。
2. "三合一 Role"（actor + rollout + ref）是 verl colocate 策略的基础，M5 会详细看。

### 关键函数 4：`TaskRunner.run()` (L291-383)

**功能**：主控流水线。注册所有 worker 角色 → 下载 checkpoint → 初始化 tokenizer/processor → 建 dataset/sampler → 构造 `RayPPOTrainer` → `init_workers()` → `fit()`。

```python
def run(self, config):
    print(f"TaskRunner hostname: {socket.gethostname()}, PID: {os.getpid()}")
    pprint(OmegaConf.to_container(config, resolve=True))      # 1. 打印完整 config（resolve 掉 ${...} 引用）
    OmegaConf.resolve(config)                                 # 2. 就地 resolve，后面访问都是具体值

    actor_rollout_cls, ray_worker_group_cls = self.add_actor_rollout_worker(config)  # 3. 注册 actor+rollout（+ref）
    self.add_critic_worker(config)                            # 4. 注册 critic（GRPO 场景其实不会被调用）
    self.add_reward_model_resource_pool(config)               # 5. 按需给 RM 分配独立 GPU pool
    self.add_teacher_model_resource_pool(config)              # 6. 蒸馏场景给 teacher 分配 pool
    self.add_ref_policy_worker(config, actor_rollout_cls)     # 7. 如果 need KL 且没融合进 actor，加独立 ref

    validate_config(                                          # 8. 全局 config 一致性检查
        config=config,
        use_reference_policy=need_reference_policy(config),
        use_critic=need_critic(config),
    )

    local_path = copy_to_local(                               # 9. HuggingFace/HDFS 路径 → 本地路径
        config.actor_rollout_ref.model.path,
        use_shm=config.actor_rollout_ref.model.get("use_shm", False),
    )

    from verl.utils import hf_processor, hf_tokenizer
    trust_remote_code = config.data.get("trust_remote_code", False)
    tokenizer = hf_tokenizer(local_path, trust_remote_code=trust_remote_code)   # 10. 文本 tokenizer
    processor = hf_processor(local_path, trust_remote_code=trust_remote_code, use_fast=True)  # 11. 多模态 processor，None 表示非 VLM

    resource_pool_manager = self.init_resource_pool_mgr(config)  # 12. 把 role → pool_name 的 mapping 物化为真正的 GPU 分配

    from verl.utils.dataset.rl_dataset import collate_fn
    train_dataset = create_rl_dataset(                        # 13. 读 parquet，tokenize，构建 Dataset
        config.data.train_files, config.data, tokenizer, processor,
        is_train=True, max_samples=config.data.get("train_max_samples", -1),
    )
    val_dataset = create_rl_dataset(
        config.data.val_files, config.data, tokenizer, processor,
        is_train=False, max_samples=config.data.get("val_max_samples", -1),
    )
    train_sampler = create_rl_sampler(config.data, train_dataset)  # 14. RandomSampler（可 resume）或 SequentialSampler

    trainer = RayPPOTrainer(                                  # 15. 构造 trainer（但还没 spawn worker）
        config=config,
        tokenizer=tokenizer,
        processor=processor,
        role_worker_mapping=self.role_worker_mapping,         #     注册表交给 trainer
        resource_pool_manager=resource_pool_manager,          #     GPU 池子交给 trainer
        ray_worker_group_cls=ray_worker_group_cls,
        train_dataset=train_dataset,
        val_dataset=val_dataset,
        collate_fn=collate_fn,
        train_sampler=train_sampler,
    )
    trainer.init_workers()                                    # 16. 真正 spawn Ray actor —— M2 的内容从这里开始
    trainer.fit()                                             # 17. 主训练循环 —— M3 的内容
```

**总结这一层的抽象**：`main_ppo.py` 做的只有 "装配"：注册 role、挑 Worker 类、分 GPU、建 dataset，然后把一切交给 `RayPPOTrainer`。不做任何实际计算。

## M1.4 — `DataProto` 类 (`protocol.py`, 90 min)

### 字段模型

```python
@dataclass
class DataProto:
    batch: TensorDict = None               # 定长张量：input_ids, attention_mask, responses, old_log_probs, advantages ...
    non_tensor_batch: dict = field(...)    # numpy object 数组：raw_prompt, tools, ground_truth 等不定长 Python 对象
    meta_info: dict = field(...)           # 纯 Python dict：全 batch 共享的标量（eos_token_id, global_step, metrics）
```

**不变式**：`batch` 和 `non_tensor_batch` 所有条目在 dim 0 必须一致（= batch size）；`meta_info` 没有 batch 维度。所有 chunk/concat/select 都围绕这个不变式展开。

### 关键函数 1：`check_consistency()` (L454-477)

**功能**：入口/出口的健全性检查，确保三字段一致。所有新建 DataProto 的 `__post_init__` 自动调用。

```python
def check_consistency(self):
    if self.batch is not None:
        assert len(self.batch.batch_size) == 1, "only support num_batch_dims=1"  # 1. 只允许单 batch 维度

    if self.non_tensor_batch is not None:
        for key, val in self.non_tensor_batch.items():
            assert isinstance(val, np.ndarray)                                    # 2. non_tensor_batch 强制 numpy 数组（不是 list）

    if self.batch is not None and self.non_tensor_batch is not None and len(self.non_tensor_batch) != 0:
        assert len(self.batch.batch_size) == 1, "..."
        batch_size = self.batch.batch_size[0]
        for key, val in self.non_tensor_batch.items():
            assert isinstance(val, np.ndarray), (...)
            assert val.shape[0] == batch_size, (                                  # 3. 核心不变式：batch 和 non_tensor_batch 的 dim 0 必须一致
                f"key {key} length {len(val)} is not equal to batch size {batch_size}"
            )
```

### 关键函数 2：`from_dict()` (L495-543)

**功能**：标准构造器。每个 `DataProto(...)` 创建场景几乎都走这里。把 dict[str, Tensor] + dict[str, ndarray] 合成 DataProto，自动校验 dim 0 一致。

```python
@classmethod
def from_dict(cls, tensors=None, non_tensors=None, meta_info=None, num_batch_dims=1, auto_padding=False):
    assert num_batch_dims > 0
    if non_tensors is not None:
        assert num_batch_dims == 1, "..."                    # 1. 只有 num_batch_dims=1 时才允许 non_tensors

    if tensors is None: tensors = {}
    if meta_info is None: meta_info = {}
    if non_tensors is None: non_tensors = {}

    batch_size = None
    pivot_key = None
    for key, tensor in tensors.items():                      # 2. 用第一个张量定 batch_size，后续所有张量必须匹配
        if batch_size is None:
            batch_size = tensor.shape[:num_batch_dims]
            pivot_key = key
        else:
            current_batch = tensor.shape[:num_batch_dims]
            assert batch_size == current_batch, (...)        # 3. 不一致直接抛，避免后续神秘 shape 错误

    for key, val in non_tensors.items():
        if not isinstance(val, np.ndarray):
            non_tensors[key] = np.array(val, dtype=object)   # 4. 自动把 list 包成 object ndarray

    tensor_dict = TensorDict(source=tensors, batch_size=batch_size) if tensors else None
    if auto_padding:
        meta_info[DataProtoConfig.auto_padding_key] = True   # 5. 打标：允许 chunk 时自动 pad 到整除
    return cls(batch=tensor_dict, non_tensor_batch=non_tensors, meta_info=meta_info)
```

### 关键函数 3：`select()` (L600-633)

**功能**：列级投影 —— 从当前 DataProto 里挑几列，不改 batch 维度。典型用法：rollout 只需要 `input_ids/attention_mask/position_ids`，避免传冗余列。

```python
def select(self, batch_keys=None, non_tensor_batch_keys=None, meta_info_keys=None, deepcopy=False):
    if batch_keys is not None:
        batch_keys = tuple(batch_keys)
        sub_batch = self.batch.select(*batch_keys)           # 1. TensorDict 原生 select —— 共享底层 tensor 存储（不复制数据）
    else:
        sub_batch = self.batch                               # 2. None 表示保留全部

    if non_tensor_batch_keys is not None:
        non_tensor_batch = {key: val for key, val in self.non_tensor_batch.items() if key in non_tensor_batch_keys}
    else:
        non_tensor_batch = self.non_tensor_batch

    if deepcopy:
        non_tensor_batch = copy.deepcopy(non_tensor_batch)   # 3. 默认浅复制；deepcopy=True 时真正复制数据

    if meta_info_keys is not None:
        sub_meta_info = {key: val for key, val in self.meta_info.items() if key in meta_info_keys}
    else:
        sub_meta_info = self.meta_info

    if deepcopy:
        sub_meta_info = copy.deepcopy(sub_meta_info)

    return type(self)(batch=sub_batch, non_tensor_batch=non_tensor_batch, meta_info=sub_meta_info)
```

**观察**：`select` 是 view 而非 copy（除非 `deepcopy=True`），所以调用方不能在 select 返回值上就地修改 tensor。

### 关键函数 4：`union()` (L781-798)

**功能**：把另一个 DataProto 的字段合并进自己。rollout 产出 `responses/old_log_probs` 后，要 union 回 prompt batch 才能进入训练 step —— 这是 veRL 里最频繁的聚合操作。

```python
def union(self, other: "DataProto") -> "DataProto":
    self.batch = union_tensor_dict(self.batch, other.batch)  # 1. 合并 batch：新 key 直接加；重名 key 必须值完全相等，否则报错
    self.non_tensor_batch = union_numpy_dict(self.non_tensor_batch, other.non_tensor_batch)  # 2. 同理合并 ndarray 字段
    self.meta_info = union_two_dict(self.meta_info, other.meta_info)                         # 3. meta_info 冲突必须相等（防 metric 乱覆盖）
    return self
```

**严格模式的意义**：如果你尝试 union 两个都有 `advantages` 但值不同的 DataProto，会立刻报错，而不是悄悄覆盖。这在调试 RLHF 多阶段拼装时很重要（避免 "advantage 对不上是因为被谁覆盖了" 的玄学问题）。

### 关键函数 5：`chunk()` (L864-903) — **M2 的基石**

**功能**：按 dim 0 把 DataProto 切成 N 份，发给 N 个 worker。`meta_info` 广播（不切）。`single_controller` 的 dispatch 机制核心依赖此操作。

```python
def chunk(self, chunks: int) -> list["DataProto"]:
    if not self.is_padding_enabled():
        assert len(self) % chunks == 0, (                    # 1. 除不尽直接报错（除非开了 auto_padding）
            f"only support equal chunk. Got size of DataProto {len(self)} and chunk {chunks}."
        )

    bsz_in_batch = None
    if self.batch is not None:
        batch_lst = self.batch.chunk(chunks=chunks, dim=0)   # 2. TensorDict 原生 chunk（等价 torch.chunk，view 不复制）
        bsz_in_batch = np.array([batch.batch_size[0] for batch in batch_lst])
        chunk_indices = np.cumsum(bsz_in_batch)[:-1]         # 3. 累积分割点，用于对齐 non_tensor_batch
    else:
        batch_lst = [None for _ in range(chunks)]

    non_tensor_batch_lst = [{} for _ in range(chunks)]
    for key, val in self.non_tensor_batch.items():
        assert isinstance(val, np.ndarray)
        if bsz_in_batch is not None:
            non_tensor_lst = np.array_split(val, chunk_indices.tolist())  # 4. 按 batch chunk 的精确分割点切 numpy
        else:
            non_tensor_lst = np.array_split(val, chunks)     # 5. 没有 batch 时均分
        assert len(non_tensor_lst) == chunks
        for i in range(chunks):
            non_tensor_batch_lst[i][key] = non_tensor_lst[i]

    output = []
    for i in range(chunks):
        output.append(
            type(self)(batch=batch_lst[i], non_tensor_batch=non_tensor_batch_lst[i], meta_info=self.meta_info)
            # 6. 注意：meta_info 是 N 份 DataProto 共享同一个 dict 引用！
            #    单个 worker 就地修改会污染其他 shard 看到的 meta_info。
        )
    return output
```

**记住**：`meta_info` 不切 —— N 个 shard 都指向同一个 dict。这既是性能优化（全 batch 共享的 eos_token_id 不需要复制 N 份），也是坑（worker 不能就地改 meta_info）。

### 关键函数 6：`concat()` (L917-961) — **collect 的对称操作**

**功能**：把 N 个 worker 返回的 DataProto 拼回一个。与 `chunk` 对称，但 `meta_info` 合并有特殊规则 —— `metrics` 字段做聚合，其他字段要求值相等。

```python
@staticmethod
def concat(data: list["DataProto"]) -> "DataProto":
    batch_lst = []
    for batch in data:
        batch_lst.append(batch.batch)
    new_batch = torch.cat(batch_lst, dim=0) if batch_lst[0] is not None else None  # 1. TensorDict 级别的 torch.cat

    non_tensor_batch = list_of_dict_to_dict_of_list(list_of_dict=[d.non_tensor_batch for d in data])
    for key, val in non_tensor_batch.items():
        non_tensor_batch[key] = np.concatenate(val, axis=0)  # 2. numpy 版 concat

    merged_meta_info = {}
    if data:
        all_metrics = []
        for d in data:
            for k, v in d.meta_info.items():
                if k == "metrics":                            # 3. metrics 特殊处理：来自多个 worker，要聚合而非覆盖
                    if v is not None:
                        if isinstance(v, list):
                            all_metrics.extend(v)
                        else:
                            all_metrics.append(v)
                else:                                         # 4. 非 metrics 字段：严格要求一致
                    if k in merged_meta_info:
                        assert merged_meta_info[k] == v, f"Conflicting values for meta_info key '{k}'"
                    else:
                        merged_meta_info[k] = v

        if all_metrics:
            merged_meta_info["metrics"] = list_of_dict_to_dict_of_list(all_metrics)  # 5. list[dict] → dict[list]，方便后续 mean/std 聚合

    cls = type(data[0]) if len(data) > 0 else DataProto
    return cls(batch=new_batch, non_tensor_batch=non_tensor_batch, meta_info=merged_meta_info)
```

**两条设计哲学**：
1. 普通 meta 字段冲突即报错（防止 worker 间不一致状态被静默吞掉）。
2. `metrics` 例外：每个 worker 算自己的数字，最终在 driver 侧聚合。

### 关键函数 7：`repeat()` (L971-1013) — **GRPO 的 N-sampling 基础**

**功能**：把每条样本复制 N 份。GRPO 场景：prompt batch size=256，`rollout.n=5`，调用 `repeat(5, interleave=True)` 后 batch size=1280，每个 prompt 连续出现 5 次，方便后续按组算 baseline。

```python
def repeat(self, repeat_times=2, interleave=True):
    if self.batch is not None:
        if interleave:
            # 1. interleave：[a, b, c] → [a, a, b, b, c, c]（每个原元素连续出现 repeat_times 次）
            repeated_tensors = {
                key: tensor.repeat_interleave(repeat_times, dim=0) for key, tensor in self.batch.items()
            }
        else:
            # 2. 非 interleave：[a, b, c] → [a, b, c, a, b, c]（整体 tile repeat_times 次）
            repeated_tensors = {
                key: tensor.unsqueeze(0).expand(repeat_times, *tensor.shape).reshape(-1, *tensor.shape[1:])
                for key, tensor in self.batch.items()
            }

        repeated_batch = TensorDict(
            source=repeated_tensors,
            batch_size=(self.batch.batch_size[0] * repeat_times,),
        )
    else:
        repeated_batch = None

    repeated_non_tensor_batch = {}
    for key, val in self.non_tensor_batch.items():
        if interleave:
            repeated_non_tensor_batch[key] = np.repeat(val, repeat_times, axis=0)   # 3. numpy 等价 repeat_interleave
        else:
            repeated_non_tensor_batch[key] = np.tile(val, (repeat_times,) + (1,) * (val.ndim - 1))

    return type(self)(
        batch=repeated_batch,
        non_tensor_batch=repeated_non_tensor_batch,
        meta_info=self.meta_info,                            # 4. meta_info 共享引用，同 chunk 行为
    )
```

**为什么 GRPO 用 `interleave=True`**：后续按组算 reward baseline 时，组内样本必须在 batch 里连续，否则要先 reorder。interleave 排布让 `rewards.view(-1, n).mean(-1)` 直接能算组均值。
